Prepare and open concise draft pull request(s) for the current branch. Extra context: ${@:-none}

Invoking `/pr` authorizes this full workflow without intermediate approval, synchronization performed by `gwsync`, and new commits containing only accepted `ponytail-review` simplifications. Existing branch commits are valid; preserve them. No other new commit is allowed.

1. Preflight. Determine current and default branches. Stop if this is not a Git worktree, no `origin` exists, `gh auth status` fails, current branch is the default branch, working tree is dirty, or an open PR already exists for the current branch. Never stash or discard work.
2. Parent and sync. Resolve the immediate parent from recorded `gh-stack` or Git Town lineage. If none is recorded, inspect branch ancestry and remote PR/stack metadata; use the default branch only when the branch is clearly direct, and ask if the parent remains ambiguous. Record the confirmed parent through the repository's existing lineage mechanism before syncing. Before any `gh stack` command, load and follow the `gh-stack` skill. Run `gwsync --no-push` through zsh if needed, then resolve the parent again. Stop on conflicts, skipped branches, or any sync failure. Parent equal to default means direct PR; any other parent means stacked PR. Use only `git diff <parent>...<branch>` for that branch's scope and stop if it is empty.
3. Choose PR shape. Inspect the parent-relative diff, changed files, and existing commits. Keep one PR when the change is cohesive and reviewable; multiple commits alone are fine. Preserve an existing stack. If a direct change is too large, touches too many files to review clearly, or contains independently reviewable dependency layers, load `gh-stack` and split it into the smallest dependency-ordered stack. Preserve commits when possible; ask before rewriting published history.
4. Review every final layer. After branch shape and parents are final, run `gwsync --no-push` from the top branch. Before any push or PR creation, launch fresh-context reviewer agents in parallel for every PR branch against only its immediate-parent diff: one for correctness, regressions, and validation; one using `ponytail-review` for unnecessary complexity. Apply every clear, behavior-preserving `ponytail-review` finding on the branch where it belongs. Run the smallest relevant existing check, stage only simplification changes, and commit them directly with concise messages. If no finding makes sense, make no changes or commits. Run `gwsync --no-push` again so descendants include updated parents, then ask fresh reviewers to verify each final parent-relative diff. Stop on any unresolved correctness finding.
5. Describe only each layer. For each PR, derive title and body only from `git diff <immediate-parent>...<branch>`; never describe inherited parent changes. Read `.github/pull_request_template.md` when present and fill it minimally. Without a template, use only a short `## Why` section. If that branch name contains a Linear key case-insensitively and this project exposes Linear MCP, read the issue for motivation; never configure MCP from this workflow.
6. Create draft PRs. For a direct branch, push normally and run `gh pr create --draft --base <parent>`. For a stack, load `gh-stack`, run `gwsync --link` from the top branch, verify every expected PR exists and remains draft, then update each new PR body with its parent-relative description.

Never run a manual force-push, merge, squash, delete branches, or modify unrelated PRs. Managed `--force-with-lease` inside `gwsync` or `gh-stack` is allowed. Stop on command failure and report exact error and every PR URL created.
